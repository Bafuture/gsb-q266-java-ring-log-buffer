## 实现说明：覆盖式环形日志缓冲

核心类位于 `src/main/java/com/example/gsb/ringlog/`：

| 类型 | 职责 |
|------|------|
| `RingLogBuffer<T>` | 固定容量环形缓冲，`ReentrantReadWriteLock` 保护槽位数组与序号元数据 |
| `LogEntry<T>` | 不可变条目（全局序号 + 载荷），发布后可安全共享 |
| `ReadOutcome<T>` | 按序号读取的三态结果：`Hit` / `Expired` / `NotYetWritten` |
| `LogSnapshot<T>` | 导出时刻的连续条目副本，与后续写入完全隔离 |
| `BufferStats` | 统计快照：写入总数、有效条数、被覆盖条数、导出次数 |

**关键语义**

- 序号从 0 起在写锁内单调分配；写满后写入覆盖最旧槽位，`oldestSequence` 同步推进为 `nextSequence - capacity`，被覆盖序号读取时返回 `Expired`（附带当前最旧序号），绝不返回错误数据。
- 槽内只放不可变的 `LogEntry`，引用赋值在同一把读写锁保护下进行，读线程看到的必是完整旧条目或完整新条目，不存在"半个条目"。
- 批量写（`addAll`）、批量按序号读（`readAll`）、批量按下标读（`range`）均为单次加锁；快照（`snapshot`）在持锁期间把有效区间复制到独立列表，并递增导出计数。

### 与无界队列方案的取舍

- 本方案：内存上限固定（只保留最近 N 条），写入永远不分配新节点、无 GC 压力尖峰；代价是超过容量的历史被永久丢弃，必须用三态结果让调用方显式处理"已失效"，不能假装数据还在。
- 无界队列（如 `ConcurrentLinkedQueue` / 无界 `LinkedBlockingQueue`）：保留全部历史，语义简单、无失效区间；代价是内存随写入量线性增长，长跑或日志洪峰下有 OOM 风险，且链表节点的持续分配带来 GC 开销。
- 结论：调试日志的价值集中在"最近一段"，因此选择以内存上限换历史长度；若需要长期留痕，应让慢速消费者（文件/网络）从快照接口持续导出到外部存储，而不是把缓冲本身扩大成无界。

## 任务提示词

以下为本题完整的 User Prompt 原文，两次执行必须使用完全相同的文本。

我们的调试日志要保留最近一段，写满后覆盖最旧的，同时读侧要能稳定按序导出。请从零实现一个覆盖式环形日志缓冲。仓库目前只有一个空的 Maven 工程（pom.xml 只声明 JUnit 5 与 AssertJ）。要求：1) 固定容量环形缓冲，写满后覆盖最旧条目，覆盖时要有明确的最旧序号推进；2) 支持按下标与按序号读取，被覆盖的序号要返回明确的"已失效"结果而不是错误数据；3) 并发安全：写入与读取并发进行时不得读到正在被覆盖的半个条目，需有测试证明；4) 支持快照导出：导出某一时刻的连续一段条目，导出期间继续写入不得破坏这份快照；5) 支持批量写入与批量读取以降低同步开销；6) 支持统计：写入总数、当前有效条数、被覆盖条数与导出次数；7) 说明与无界队列方案的取舍（内存上限换历史长度）；8) 测试覆盖覆盖策略、失效读取、并发不撕裂、快照隔离、批量操作与统计；`mvn -q verify` 一条命令跑通。
